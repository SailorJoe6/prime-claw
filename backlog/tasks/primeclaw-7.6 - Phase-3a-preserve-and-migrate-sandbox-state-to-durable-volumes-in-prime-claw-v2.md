(5) Verify actual mounts, PostgreSQL recovery and both database aggregates/dimensions, Git refs, required Prime Agent state, and one basic Prime Agent session before making v2 active. Keep Phase 3a source/index and routed-write gates blocked until their own acceptance. (6) For later v3+ rebuilds, audit new writes during use and before every rebuild; quiesce writers, migrate accepted paths into mounted storage, and create a new version when mount changes require container replacement. Maintain an independent backup of the volume.

Use project apply/check/validate recovery discipline. Do not run the existing force-fresh delete path or directly Docker-start the Error-state container.
