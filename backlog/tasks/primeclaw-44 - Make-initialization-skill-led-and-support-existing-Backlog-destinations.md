## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## Outcome
Make the initialization and Beads-to-Backlog migration experience usable through one agent-guided Markdown skill. Correct the reported setup and migration admission problems without redesigning the existing Beads issue importer.

## Context
Live ralph-pva initialization exposed four issues: the custom initialization slash command exposes an agent-oriented interface to the operator; customized-skill comparisons temporarily overwrite real files; migration rejects an existing Backlog destination rather than preserving it; and source capture requires unused Prime Claw custom lifecycle statuses in the Beads store being retired. The reported project already has Backlog tasks and configuration as well as Beads issues. Their coexistence is expected input to this explicit one-way migration, not ambiguity in the operator's intent. A second retiring-source admission failure was confirmed in nemo-setup with native bd 1.3.1 embedded mode: the canonical migration unconditionally requires server-mode transport, SQL inventory/revision checks unavailable in embedded mode, and a server-stop retirement step. Installed source and repository main had no bypass-free fix at triage. Existing disposable backup/restore and attachment probes do not prove a complete live-source capture or successful corpus/history migration. The retiring source need not be configured or published like an active Prime Claw Beads provider.

## Required behavior
- Provide one initialization Markdown skill covering setup, upgrades, comparisons, and migration. The agent uses the underlying initialization tool; the operator need not learn its action arguments. Replace the custom initializer slash-command interface with skill-led guidance. Do not add a separate migration skill.
- Generate a standard Git diff for comparison and let the operator read the patch as text. No specialized viewer is required. Generating or displaying a comparison must not temporarily overwrite, stage, or restore the actual skill or workflow files. Reviewing a patch does not accept an override or reset an asset. Preserve project customizations and do not silently discard existing interrupted-review evidence.
- The provider migration operation is Beads to Backlog only. An existing default backlog/, standard .backlog/, or custom Backlog store selected by root backlog.config.yml is a destination to preserve and merge into, not a reason to reject migration or ask for separate preservation approval.
- Keep existing Backlog task IDs unchanged. Preserve all existing tasks, including archived records, their contents/history, and configuration; never replace existing configuration with fresh defaults. During installation/initialization as well as Beads migration, move the default dedicated backlog/ store into the new standard .backlog/ layout with the standard native root configuration symlink; an existing .backlog/ remains there. This normalization also applies to Backlog-only projects. Exception: a custom dedicated Backlog folder selected by root backlog.config.yml must stay at its configured location and be handled in place during installation and migration, with its configuration preserved; do not force it into .backlog/ or impose the default layout on it. Use native configuration evidence to identify the store, not a directory name alone. Do not leave a relocated default backlog/ as a second live store.
- Reuse the existing Beads issue migration behavior. Do not redesign how its IDs, fields/statuses, history/provenance, or relationships are migrated, introduce new ID-allocation or deduplication policy, or add a new semantic-placement mechanism. The previously supported legacy open to In Design and closed to Done mappings remain the baseline. Correct the erroneous classification of every closed issue as archived: ordinary closed means Done/completed, not abandonment. Archive only with exact positive prior-archive/Prime Claw abandonment evidence or an explicit task-specific operator decision; a nonempty close_reason, keyword match, or status category alone is not sufficient. Preserve raw status/category context, close_reason, and native history, and verify native destination status and physical task/completed/archive placement. The tentative deferred-to-drafts suggestion is not approved new mapping scope.
- Treat Beads as a source being retired and read its existing data as-is. Do not require server mode, Prime Claw lifecycle status definitions, a Dolt remote, source publication/push, engine conversion, or configuration changes. Separate the actual capture requirements—correct source identity, a complete stable capture of existing issues and required native history, and faithful destination verification—from active Beads lifecycle/write readiness. Use supported native reads or isolated native evidence without assuming embedded SQL or server-only commands exist. If source data cannot actually be read or captured completely, stop with the precise data/capability problem and leave the source intact; do not turn that into a demand to reconfigure Beads. Apply this boundary through inspection, recaptures and retirement; active Beads execution safety remains unchanged.
- Keep explicit migration confirmation, correct source/destination identity, complete capture, quiescence, ownership continuity, and verified cutover. Verify and publish the Backlog destination before retiring Beads. Publication is a destination guarantee, not a requirement to configure or publish the outgoing Beads store. Genuine unreadable data, an incomplete or unstable capture, unsafe ownership, or an unverified destination still prevents retirement.

## Consolidated PRIMECLAW-46 findings and regression requirements
PRIMECLAW-44 is the implementation scope for the overlapping legacy-source bug. PRIMECLAW-46 retains the published investigation and reproduction evidence (investigation commit 5d520d3); its separate plan at b19932f is superseded, not a second implementation task. In particular, that plan's outgoing-source server/publication requirements must not override this specification's as-is embedded/local-only source support.

- The unused-status gate is nested in both source capture and transport, and is also reached by source active-Episode workspace proof and later rechecks. Correct the source-read boundary through the complete inspection/recapture/retirement path, not only the first capability call. Keep ordinary active Beads lifecycle/write checks strict; do not add a general validation bypass.
- Retain the complete native status catalog and source version, including categories/descriptions/custom context, in the existing stable capture and verified destination provenance. Detect task or status-definition drift before cutover without requiring the retiring source to have a remote or published revision. Use supported native evidence, not a new persistent snapshot service or workflow state machine.
- Inspect the complete actual status inventory before any destination mutation. Reuse supported mappings; for deferred/pinned/hooked or custom statuses without a supported projection, and genuinely ambiguous archive evidence, report exact task IDs/statuses and stop with source and destination intact. Do not silently omit tasks, guess semantics from categories, or implement deferred-to-drafts. Counts, native writes, and verification must agree on completion versus archive placement. Resolving material semantics is agent/operator judgment, not a new deterministic reconciliation or heuristic classification engine.
- Disposable regressions must cover built-in-only and partial-custom catalogs, ordinary completed closed issues versus positively evidenced archive/abandonment, complete mixed-status preflight refusal, catalog/reason/history preservation and capture drift, active-source ownership continuity, repeated source checks, and confirmed end-to-end migration before retirement. Correct fixtures that configure every custom status and model all closed issues as archived. Retain complete-inventory, unstable/unreadable-source, ownership, receipt, destination-publication, and cutover/deletion refusal coverage; source publication is not an added requirement.

In particular, the reported two active Backlog tasks plus an archived prefix-probe record must not be silently removed or renumbered. Do not broaden this work into removing ordinary Beads execution support, changing task lifecycle policy, implementing a viewer, or rewriting Prime Agent. Implementation, merge, global activation, and any live migration require their separate normal authority.
