# Daily prime-claw sync (Orca automation; manager runbook)

This is an Orca automation, **not** `prime-agent schedule`. The canonical checkout is `/home/sailorjoe6/Code/prime-claw`, `main` tracking `origin/main`. Manager Prime Agent conversation: `Prime-Claw Daily Maintenance` (session ID `01a1eb77-824d-725c-b5dd-3a313b28cf83`). The automation worker must check in with this exact manager at the start and at the end using `prime-agent send <session-id> <message>`, recording the CLI delivery result; use Orca's saved automation run to identify its own session. Do not address a different conversation if the manager cannot be reached. Keep the run open and escalate if delivery fails. A delivered check-in is not proof that the manager has completed the corresponding action.

## Worker contract

1. Send a **starting** message with automation run/session identity, checkout, timestamp, branch, old HEAD and initial `git status --short`. If delivery fails, stop before touching Git and leave an Orca run failure for recovery.
2. Work in the canonical checkout only. Before mutation, verify `git rev-parse --show-toplevel`, `git branch --show-current` = `main`, `git remote get-url origin`, and `git status --porcelain=v1`; inspect index, conflicted paths, and ongoing rebase/merge. Stop on unexpected state instead of resetting/cleaning/force-pulling. Never move live `.beads/` Dolt database/lock/port/log files, credentials, or other ignored runtime data into a stash. Do not touch unrelated worktrees or active Episode state.
3. Record HEAD and the stash list/hash. Fetch `origin`; if tracked or ordinary untracked changes exist, stash them with a unique descriptive timestamped `git stash push --include-untracked` using pathspec exclusion for `.beads/`; verify the exact new stash OID and clean tracked/index state. If only `.beads/` runtime files remain, proceed without stashing them. If there are untracked paths that collide with incoming tracked paths, stash those ordinary files; fail safely if the runtime path collides. A stash cannot represent ignored files: leave ignored runtime state intact.
4. `git pull --rebase origin main` (or `--ff-only` when strictly behind and no local commits). If it conflicts, handle only clear mechanical conflicts with evidence; otherwise stop, preserve the stash and Git conflict state, report the exact blocker. No hard reset, force push, destructive cleanup, or dropping another person's commits.
5. Restore the exact newly created stash with `git stash pop <exact-stash-reference>` and resolve straightforward conflicts in scope. On unresolved conflict leave the stash intact (Git normally keeps it), do not claim success, report precise paths and next decision. Check `git status`, current HEAD, upstream relationship, and whether original edits/untracked content survived; preserve old stashes untouched. Never blindly reapply stale changes to deleted/renamed files: use the new location if unambiguous, otherwise report and preserve.
6. Diff the old and new HEAD for `src/prime-agent-plugin/` and related install/managed assets. Send a **done** message with old/new HEAD, commit summary, plugin-changed flag, exact stash OID/state, conflicts, and `git status`; send even on failure if possible. Do not install the global plugin, coordinate other sessions, restart Prime Agent, delete another agent, or claim that manager-only work completed. Finish the Orca run with a truthful success/failure outcome and leave enough run/session identity for the manager to close it.

## Manager contract on worker start/done

- Verify the worker's check-ins and Orca run identity. Do not assume scheduled delivery or a "done" message proves Git success; inspect the evidence. If no done message, use `orca automations runs` and the exact session to recover. Do not close an active or unverifiable worker.
- After worker completion, match the day's automation run `terminalPaneKey` to `orca terminal show --terminal <handle> --json`; only for that exact disposable Codex terminal run `orca terminal close --terminal <handle> --json`. Verify `ptyKilled: true`, no Codex agent remains in the checkout's `orca worktree ps --json` row, and the automation run changes to `completed` (or report failure). Never close another terminal, this manager conversation, or another user's session. Orca run history remains as an audit trail; do not claim external Codex history files were deleted. If the run uses a chat or the exact handle cannot be proven, report the limitation and keep its run ID for cleanup.
- If the old..new HEAD changes plugin source or managed plugin assets, review the accepted `main` contents and compare installed generation. Only from the primary `main` checkout run `scripts/apply-prime-agent-plugin.sh --user-global` and `scripts/check-prime-agent-plugin.sh --user-global` (post-acceptance global refresh, never a candidate apply). Keep the repo's `.prime/agent/extensions/` empty of duplicate plugin source. If either fails, stop and report; do not restart into an unverified install.
- Before a **full** Prime Agent restart, enumerate active sessions with authoritative `prime-agent sessions --all --json` and/or `agent_observe.list_agents()`. Tell each live session the planned maintenance window via `agent_message` when it is a reachable sibling; for others use the documented `prime-agent send` route. Ask them to reach a stopping point and acknowledge quiescence; never kill a running worker, mistake idle for an acknowledgment, or assume the manager's own session can survive restart. Defer restart if anyone cannot safely quiesce, and report remaining work. After acknowledgments, use the supported Prime Agent shutdown/restart procedure from an independently running Orca control terminal, not a shell command whose parent Prime Agent dies halfway through; prove daemon restart and resumed owner/Episode/ordinary-session UAT, not just successful file copy or `/reload`. Preserve resources until UAT. Recheck installed plugin after restart. If reliable restart handoff or all acknowledgments are unavailable, leave the verified install staged and escalate rather than force shutdown.
- On a day without a plugin change, no global install or restart is needed. Report Git outcome, worker cleanup and any outstanding blocked step to the operator.

Use `orca skills get orca-cli` and `orca skills get orchestration` with this host's version-matched binary before Orca operations. Resolve `ORCA_CLI_COMMAND` first; outside managed terminals on Linux select `orca-ide`, never bare GNOME `orca`. Avoid raw `git worktree` where Orca workspace state matters.
