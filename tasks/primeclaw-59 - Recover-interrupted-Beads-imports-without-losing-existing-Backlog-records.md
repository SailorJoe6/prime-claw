## Problem
During the operator-approved ralph-pva Beads-to-Backlog migration, the synchronous migration worker stopped without a result after writing 146 task files. All files were generated by the import. The last provenance package had only 58 of 72 chunks. Beads remained intact and authoritative; no completion receipt existed. Explicit same-revision retry then failed before cutover with `source task history is not clean: ?? tasks/`. The current replay path requires a clean published destination and a full receipt, so it cannot recover an interrupted pre-receipt import.

## Observed preservation gap
The project also has three original `backlog/` records (RPVA-1, RPVA-2, and a distinct archived RPVA-2) and `backlog/config.yml.pre-migration`. That config was parked under an earlier operator-authorized workaround. Fresh destination preparation treats the parked store as absent: the original records remain physically preserved but are not consolidated into the selected `.backlog/`. A disposable fixture reproduced this; restoring the original config alone instead hits the exact lifecycle-status capability gate. This is not permission to omit, renumber, overwrite, or delete old records/history.
