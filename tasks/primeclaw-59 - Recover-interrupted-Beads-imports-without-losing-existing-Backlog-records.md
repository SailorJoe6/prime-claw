## Description

## Required migration scope — operator clarification
Joe explicitly clarified: "We only need to migrate the current state of the ticket from beads to backlog!" This supersedes earlier wording that treated importing full source history or lossless revision archives as a requirement.

Migrate each ticket's current readable content and supported metadata: title, description, acceptance criteria, current plan/design and notes, current lifecycle status/close information, priority, type, labels, assignee, parent/dependency relationships, and actual existing ticket comments. Preserve meaningful current fields through corresponding native Backlog fields or concise labeled readable text when no equivalent exists. Actual authored comments are ticket content; Dolt revision snapshots, database events, and old field versions are not.

Do NOT migrate per-ticket Dolt revision history, old ticket snapshots, database event streams, base64 export packages, or archive blobs into Backlog tasks, comments, documents, or a newly invented archival destination. Do not merely move the encoded data elsewhere: importing it is unnecessary. Do not collect full per-ticket revision/event histories as a prerequisite to migrating current state. JSON is acceptable internal transport; it is not a reason to embed encoded source archives into human-facing task Markdown. Do not duplicate whole-store catalogs/memory snapshots inside each ticket. Existing history already held by the destination need not be rewritten or deleted.

## Recovery identity guarantee
Unfinished import records do not have a stable Backlog-ID guarantee. An operator-authorized recovery may recreate records proven to be generated by the interrupted import, unfinished, and unmodified by users. Original Backlog records, IDs, configuration, and history remain protected. Records with user changes are not disposable. Recovery must leave one complete verified import per source ticket, not duplicate or incomplete destination tickets; this does not require a fully resumable importer.

## Current defects and impact
During the first approved ralph-pva migration, the worker stopped without a result after writing 146 task files. All were generated by the import; the last provenance package had only 58 of 72 chunks. About 90 MB and 3812 native comment writes accumulated over 97 minutes. Beads remained intact and authoritative; no completion receipt existed. Same-revision retry failed before cutover with `source task history is not clean: ?? tasks/`, because replay requires a clean published destination and a full receipt rather than handling pre-receipt interruption.

Joe authorized deleting only the disposable partial `.backlog/` and generated layout projection, leaving Beads, the original `backlog/`, and the published bootstrap branch intact, then retrying. He subsequently deliberately aborted that recovery with `prime-agent shutdown --force` because ordinary interruption did not stop it and it had run over half an hour. The tool reported `append Backlog provenance to TASK-52: backlog command: command/capture failed (status=1, nativeStatus=null, signal=SIGTERM)`. Read-only inspection then found 59 task files, 1671 encoded chunks, and 39,760,679 bytes. This SIGTERM reflects operator shutdown; the earlier interruption cause remains unknown. No restart is authorized by this task update.

The unnecessary encoding is implemented by `backlogSourcePackage` (current data plus history/events/provenance and repeated source context), `chunkComment` (base64 in 24000-character pieces), and one separate `backlog task edit --comment` process per piece. This directly contributes to unreadability and runtime. The correct scope is current-state migration, not a more efficient way to archive all revisions. PRIMECLAW-50's former output-buffer defect is already fixed and is not this requirement error.

## Existing destination preservation and layout
The project also has three original `backlog/` records (RPVA-1, RPVA-2, and a distinct archived RPVA-2) plus `backlog/config.yml.pre-migration`, parked under an earlier authorized workaround. Fresh preparation treats that parked store as absent: the records remain physically preserved but are not consolidated into selected `.backlog/`. Restoring its config alone hits the exact lifecycle capability gate. Preserve existing records/configuration and distinct same-ID archive/live records without renumbering or omission.

Migration may add statuses needed by imported tickets when they are missing from the existing Backlog destination configuration. Retain existing statuses and unrelated settings; do not replace customization or demand one exact status list/order. This permission applies to Backlog only, not the retiring Beads source. Preserve and reconcile the known parked configuration under the same rule.

Native Backlog discovers `.backlog/config.yml` without a root link. Prime Claw creates `backlog.config.yml -> .backlog/config.yml` and adds `/.backlog/` to .gitignore; it does not ignore the root link. The published task-history bootstrap e48f9069d1c074b20129443a4df8371b5ac80951 has only TASKS.md/config.yml, and a disposable fixture proved it reusable after local rollback.

- [ ] #1 The migration copies each Beads ticket’s current readable fields, meaningful current metadata, actual authored comments, and parent/dependency relationships into native Backlog equivalents or clearly labeled readable current-state text.
- [ ] #2 The migration neither requires nor imports Dolt/git-like revision history, old task snapshots, or database event history; no base64 export/history packages or equivalent archive blobs are embedded in tasks/comments or relocated to a newly created archive destination.
- [ ] #3 Source/history completeness checks and destination verification are scoped to current ticket state, including relationships and actual comments, rather than historical revisions; a small current ticket with a long Dolt history does not trigger full-history capture or history-sized output.
- [ ] #4 An operator-authorized interrupted import can recover through the exact existing destination or a bounded proven-disposable reset. Generated, unfinished records with no user changes may be recreated without preserving their allocated IDs; original records/IDs/configuration/history and user-modified records remain protected. Recovery leaves one complete verified import per source ticket, with no premature source retirement.
- [ ] #5 Existing Backlog records/configuration are preserved and reconciled, including a known parked legacy config and distinct live/archive records sharing an ID; existing destination history is not needlessly rewritten or deleted. Missing statuses needed by imported tickets may be added to Backlog while retaining existing statuses and unrelated settings; no exact status list/order or Beads configuration change is required.
- [ ] #6 Ordinary supported cancellation promptly stops provider writes without force-shutting down the Prime Agent runtime and reports the stopped state with safe recovery evidence.
- [ ] #7 Representative current-state migration performance is measured, progress/elapsed time are visible, and the importer avoids thousands of sequential CLI edits caused by unnecessary encoded revision chunks.
- [ ] #8 Disposable tests cover readable current-state content, actual comments versus historical events, current relationship/status mapping, long-history sources without historical import, interruption/cancellation, same-destination recovery, and original Backlog coexistence.
- [ ] #9 Documentation distinguishes native Backlog requirements from Prime Claw layout conventions and describes bounded rollback/retry without deleting authoritative source or unrelated user data.
