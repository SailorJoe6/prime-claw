## Description

## Why
The Conversation role currently works but combines normal skill guidance with hash-authenticated guide disclosure, context filtering, in-memory receipts, duplicate ownership records, recovery states, and direct worktree/session mechanics. This exceeds the threat model of a trusted knowledge-worker plugin and conflicts with the skill-based role direction established by PRIMECLAW-10.36.

## Operator direction
- Extend the product architecture to include Orca for operator-visible scheduling, remote/supervised agent coordination, and especially native worktree creation and management, while retaining Prime Agent for sessions, REPL state, messaging, compaction, heartbeats, and lightweight recursive reasoning.
- Make `src/prime-agent-plugin/skills/` the source location for every Prime Claw-shipped skill.
- Separate globally installed skills from project-template skills. Project workflows are installed as customizable regular files into initialized projects rather than retained under legacy `.ralph/skills` plus `.agents/skills` symlinks.
- Add an explicit `/initialize-prime-claw` command and matching model-callable tool to initialize an arbitrary project after global plugin installation.
- Preserve the native command and planning/Episode-boundary tool behavior that has proven effective, apart from separately reviewed naming changes.
- Simplify the managed Conversation guide and lifecycle/state machinery to what the product needs for ordinary correctness, crash/network recovery, and bounded operator authority; do not harden against a hostile same-user filesystem or forged transcript unless evidence changes the threat model.

## Work
Design and implement the simplified Conversation architecture, including skill packaging/installation scopes, idempotent project initialization, possible `plan` → `plan-spec` naming, removal of guide authentication/disclosure machinery, hook reduction, a single minimal ownership record, Orca integration boundaries, and thinner Episode allocation/finalization mechanics. Preserve project-customizable workflow Markdown and explicit operator gates.

## Evidence-backed product design

### Markdown assets and project topology
1. Every shipped Markdown asset has one source under `src/prime-agent-plugin/` and explicit metadata for scope, exposure, customization policy, destination, and lifecycle trigger.
2. Global discoverable skills: `goals-and-heartbeats`, `prime-claw-expert-review`, and `prime-claw-oversee-episode`. Global internal assets: `ROLE_KERNEL.md` and the goal-continuation reminder fragment.
3. Project discoverable skills are regular customizable files in `.agents/skills/`: `blocked`, `design`, `execute`, `prepare`, and `spec-it-out`. `execute` is both discoverable and lifecycle-invoked.
4. Project-internal customizable workflows live in `.prime-claw/workflows/`: `handoff`, `implement-prep`, `implement-spec`, `plan-prep`, and renamed `plan-spec`. They are not slash skills; native commands load them at lifecycle boundaries.
5. Retire `.ralph/skills` and its symlink topology. Do not move or redesign `.ralph/plans` in this issue.

### Initialization and continuous reconciliation
6. `/initialize-prime-claw` and model-callable `initialize_prime_claw` share one deterministic reconcile implementation. It never commits.
7. Resolve the nearest Git worktree root using Git-equivalent behavior. Starting below the root needs no confirmation. Reaching the user's HOME before a Git root is a hard no-mutation error. Nested repositories, submodules, and linked worktrees target their own nearest root and report the detected type.
8. Track `.prime-claw/templates.json` with asset identity, upstream/baseline hash, installed or accepted-override hash, and provenance metadata, but no duplicate template contents.
9. Reconcile creates missing assets, updates only files matching their recorded baseline, preserves customized/unknown assets, applies unrelated safe updates, and reports unresolved comparisons. No automatic three-way merge in v1. For customized-template review, first explain that the operation will temporarily overwrite the clean tracked path and foreground its Orca worktree, then wait for the user to say they are ready; cancellation before readiness changes nothing. After approval, write the upstream template, focus Orca's ordinary working-tree diff, hold the overwrite until explicit completion or cancellation, then restore in finally-equivalent cleanup with `git restore --worktree` and verify the path/index clean. Refuse dirty or non-restorable paths, preserve ambiguous interrupted state for an explicit restore/keep decision, and use `git diff --no-index` only as a terminal fallback. Do not invoke Orca Computer Use, macOS Accessibility, or another OS GUI-control surface without separate explicit user approval.
10. `/initialize-prime-claw` is both first-time initialization and explicit upgrade/reconcile. There is no separate upgrade command.
11. Every ordinary Prime Agent session start in an Orca-registered Git project awaits full deterministic reconciliation before any user assignment. A current project is a no-op. Safe updates apply, customization is preserved, and one concise notice reports changes/conflicts without a model turn. Orca may supply the fixed initial Episode prompt through its native `prime-agent` provider because Prime Agent awaits `session_start` before interactive prompt processing; the live provider probe proves this ordering.
12. Do not reconcile an active Episode worktree. It keeps the workflow snapshot present at Episode creation. Ordinary Conversation/project sessions and future Episodes receive updates.
13. Initialization checks Orca registration by exact project path. Reuse an existing registration without changing metadata; add it idempotently only when absent. A Prime-Claw-mediated add continues the same reconcile operation rather than recursively invoking a command.
14. Global plugin-managed assets are not the normal customization surface, but upgrades never silently destroy edits. Detect drift and offer backup/reset/review. Kept or manually merged edits become explicit local overrides; later upstream change produces a new comparison.

### Frozen Orca and Prime Agent boundary
15. Orca owns Git worktree placement, host/setup selection, terminal/process hosting, rendered observation, host-scoped search, human ADE tabs, and exact workspace reconciliation/cleanup. Prime Agent owns durable agent sessions, native sibling messaging/roster, RLM delegation, goals, and heartbeats. Prime Claw owns exact-folder approval binding, semantic-to-mechanical lifecycle transitions, the minimal ownership record, and safe recovery policy.
16. Normal Conversation/Episode supervision does not add Orca Run/Task/Dispatch orchestration. One narrow creation-time exception uses a disabled, manually-run existing-workspace automation to launch the native reusable Prime Agent provider session after deterministic bundle promotion; remove it after successful binding. No automation drives later Episode continuation. Prime Agent RLM never substitutes for Git/worktree isolation, and heartbeats never become a workspace scheduler.
17. Before external mutation, persist one provisioning ownership record for the exact approved folder, selected project-host setup, base ref, and creation operation. Create the Orca worktree with no agent, prompt, or `--activate`; record its exact identity/path/generated branch/head. Deterministically overlay the approved folder, promote it into active `.ralph/plans`, verify the canonical checkout unchanged, and commit the promotion. Then create a disabled existing-workspace automation with `provider: prime-agent`, `reuseSession: true`, and the one fixed execute assignment; run it manually. Bind the exact-CWD durable Prime Agent session and connected background tab, remove the automation without stopping the tab, and transition ownership active. Native `agent_message` owns later supervision. Orca GUI/RPC supports generated, overridden, and reused branches, but the 1.4.223 CLI omits `branchNameOverride`; automated v1 records the CLI-generated branch rather than claiming an Orca product limitation. `pi` is a different TUI ID.
18. One ready project-host setup is used directly. Multiple ready setups open a native picker labeled with project, environment/machine, platform when known, and path. Labels are never identifiers. `/implement-spec <folder> --host id:<setup-id>` is the power/noninteractive bypass and maps to Orca's exact project-host-setup ID plus its routing environment. Cancellation or noninteractive ambiguity creates nothing. Prime Claw performs this gate because Orca otherwise selects its first candidate.
19. Remote Episode placement is disabled in v1. The current project has no ready remote setup, and Orca 1.4.223 exposes no exact approved-bundle/patch/file transport into a remote worktree. Prompt prose is not transport. Enabling remote placement requires a separately accepted transport design and end-to-end evidence.
20. Direct local fallback is allowed only when Orca is definitely unavailable before any mutation. Once Orca creation is admitted, succeeds, or is transport-ambiguous, preserve Orca ownership and reconcile by exact setup/worktree/path/identity/branch/head/terminal facts. A terminal launch failure is recovered in that worktree or surfaced; never create a duplicate direct-Git fallback.
21. Recovery keys on durable Prime Agent session ID/file and Orca worktree identity. Terminal handles and `activeSessionId` are refreshable routes: re-list after restart/staleness, path-search/resume the saved Prime Agent session, and never dual-send to old and replacement handles.

### Conversation and Episode lifecycle
22. Rename reviewed planning consistently to `/plan-spec`, internal workflow `plan-spec`, and model tool `plan_spec`; preserve compact-first sequencing.
23. First load full `prime-claw-oversee-episode` guidance during `/implement-spec`, after compact-first preparation and before semantic readiness/Episode creation.
24. After each actual compaction while the Conversation owns an active Episode, the awaited `session_compact` handler appends one durable full-guide message with `triggerTurn:false`. Ordinary, Episode, foreign-owner, and no-owner sessions receive none. A later distinct compaction appends one new message. The guide reminds the agent to follow global `goals-and-heartbeats`; do not inject that second full skill.
25. Remove guide runtime SHA/version authentication, project collision rejection, canonical-file policing, activation/disclosure/readiness tools, receipts, exact transcript-pair observation, pending/consumed state, replay redaction, and duplicate-event journals. Template hashes remain upgrade provenance only. Do not invent a duplicate-hook failure mode unsupported by Prime Agent's one-saved-compaction/one-post-hook contract.
26. `/implement-spec` is one user action. Any exact-folder pending state is a minimal ephemeral sequencing guard for its compact-first chain, not another approval UX. An interrupted pre-creation chain fails visibly and is rerun.
27. A fresh Episode inherits no Conversation transcript. Its one initial assignment is the fixed execute prompt admitted by the temporary native-provider automation only after deterministic bundle promotion. Do not send an additional daemon prompt or run initial handoff solely to compact nonexistent inherited context. Native `agent_message` begins with later supervision.
28. Keep one project-level durable ownership record with owner Conversation session ID, approved bundle location, Episode durable session ID/file, current routing ID, Orca project-setup/worktree identity, lifecycle engine, and status. Do not duplicate Orca state or retain a detailed lifecycle journal. Preserve resources and report only genuine uncertain external outcomes.
29. Semantic readiness and terminal judgment live in skills. Branch/worktree/session/ownership mutations remain deterministic tools. Finalization judgment is operator-bounded; bookkeeping close is narrow and deterministic.
30. Conversation supervision includes evidence review, bounded revisions, native Episode handoffs/continuations, Expert use when warranted, and `goals-and-heartbeats`. Goal continuation remains a reminder, not a scheduler.
31. Operator authority remains exclusive for product/scope changes, merge, abandonment, destructive cleanup, and unapproved transport.
