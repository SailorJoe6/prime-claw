# Oversee one owned episode

Use only for this Conversation's active Episode. In canonical primary, select the `.prime-claw/ownership.json` entry keyed by its exact `ownerSessionId`; accept direct migration records; ignore others. Version 1 selects retained folder oversight; version 2 selects task-native oversight. Tags never override it.

For version 2, select the provider only from that exact owner. A provider-absent record, or `provider: "backlog"` without `providerRevision`/`taskEvidence`, is grandfathered branch-local Backlog and retains its exact task ID/path. A `provider: "backlog"` record with both fields is independent Backlog history: `baseRef`/`head` bind code, while the 40-hex `providerRevision` and complete native task view bind the separately published task branch. Reload through the structured interface. Its supported fields are the sole durable product and execution contract. Never consult `.ralph/plans` in this mode. In branch-local mode the Episode owns task content on its code branch and the Conversation owns lifecycle status on main. In independent mode both use their ignored nested clone, and task commits/pushes never enter the code DAG.

A `provider: "beads"` record has no `taskPath`. Bind its task ID, published `providerRevision`, complete raw `taskEvidence`, code `baseRef`, worktree/branch, and Episode session. In main and Episode contexts, use `bd context --json`, one supported `bd dolt pull`, and exact `bd show TASK-ID --json --long --include-comments` reads; never force, retry uncertain transport, or use raw Dolt writes. Preserve native field shape and absence; never invent a normalized task, path, digest, receipt, or alternate authority.

For retained version 1 folder ownership, require a readable non-empty active specification and plan in its worktree, accepting `EXECUTION_PLAN.md`. Bind the active specification to the exact source location and accepted digest in `.prime-claw/legacy-specifications.json`, even when the original future source is absent. Keep that pair active through blocking, candidate review, and revision: the specification stays frozen and the plan stays living. A missing pair is never live and never switches modes; use exact operator-authorized version-1 recovery, verify its blocked specification against the same inventory before restoring it, and never require a task provider. Use only legacy `handoff_spec_episode` and `finalize_spec_episode` paths. Never claim task-native status or cleanup authority. Without ownership, old in-place work is not an Episode.

Use the exceptional `transition_spec_episode_to_task` cutover surface. Require marker, review, merge, activation, restart, UAT, readiness, and heads. It preserves histories, operation, resources, and active pair; creates nothing and keeps version 1 on failure. For Beads, require continuable historical-head ancestry. Re-prove clean code after final provider read. An exact same-binding replay is the only idempotent replay; plan deletion remains a separate reviewed step.

Review one reported slice at a time. Check ownership, pushed head, diff, tests, docs, authority, and worktree. For Beads, compare the persisted raw task and revision with the synchronized current raw task, publication ref, candidate code base/head, tests, and documentation. An unrelated-task revision descendant alone is compatible. For a same-task change, surface the exact persisted and current fields. Use bounded LLM judgment to decide whether it is a compatible in-scope clarification or living-plan update; escalate a genuine semantic conflict, authority change, scope expansion, or product decision. Never replace this judgment with a classifier.

A report, findings, and Review conclusions are evidence, not approval. Choose one disposition:

- **Accept and advance** when scope and evidence are sound. For Beads, `handoff_task_episode` supplies exact previous/current native context to the existing Episode LLM. Compatible owner-authored, outside same-task, and unrelated descendant changes continue without another authorization interface.
- **Request an in-scope revision** for a material contract defect. Record it through canonical handoff with `handoff_task_episode`. For Beads, guidance supplies only bounded focus; the host supplies exact factual observations. In task mode, do not edit, copy, or mirror Episode-owned task content.
- **Pause** without a product decision.
- **Consult the operator** for scope, product, merge, abandonment, cleanup, conflicting evidence, or blockers.
