# Oversee one owned episode

Use this only when one durable Prime Claw ownership record says this Conversation owns one active Episode. Keep authority modes disjoint.

For version 2 task-native ownership, bind the exact Backlog task ID and project-relative task path. Reload it through the supported structured interface in main and the Episode. Supported fields are the sole durable product and execution contract. Never consult `.ralph/plans` in this mode. The Episode owns task content on its branch; the Conversation owns lifecycle status on main. For retained version 1 folder ownership, keep the approved specification and plan.

Review one reported vertical slice at a time. Check ownership, candidate, diff, tests, docs, push, worktree, and, in task mode, ID, path, parent, content, evidence, plan, notes, and summary. A report is evidence, not approval.

Choose one disposition:

- **Accept and advance** only when scope and evidence are sound.
- **Request an in-scope revision** only for a concrete contract defect. Record it before continuation. In task mode, use exact task handoff; do not edit, copy, or mirror Episode-owned task content.
- **Pause** without a product decision.
- **Consult the operator** for scope, product, merge, abandonment, destructive cleanup, conflicting evidence, or blockers.

Never steer through ordinary chat. Continue only by canonical handoff to the exact idle Episode. Do not retry uncertain transport.

For an accepted task candidate with no fixes, never hand off or request merge from that head. The handshake must publish `Ready for Merge`, integrate main in the Episode, preserve task content and parent identity, push a two-parent candidate, and verify head, ancestry, digest, hierarchy, and status. Only then request the operator's merge decision.

On that candidate, **Delay** is a strict no-op. Delay is not abandonment. Apply **Request Changes** only after the operator explicitly chooses it. Publish exact-task-only `In Progress`, integrate it while preserving content and identity, push and verify, then hand off. Retry failed integration from its returned publication without repeating status.

Apply **Merge** only when the operator explicitly authorizes the exact verified task, main, and candidate. Fast-forward only to that candidate; never force or rebase. On retry, accept only exact prior main, candidate, dirty `Done` task, or task-only child. Immediately publish `Done` through Backlog and commit only the task. The local `Done` commit is authoritative. Verify code, content, path, parent, and status. Keep active ownership and Episode resources.

Apply **Abandon** only after explicit operator confirmation binds exact owner, task path, main head/status, Episode head, candidate/main relationship, parent, and Episode task digest. Reject any archive destination tracked at the bound main head and any inbound task links before mutation. Select only that task blob. Reapply captured status through Backlog, add the truthful Final Summary, prove no Episode code entered main, archive without `Done`, and commit/push the exact move. Retry only exact task-preparation, archival-move, or archival-child states. Keep active ownership and every resource; cleanup needs separate authority.

When required, use `prime-claw-expert-review`. Treat every review conclusion as evidence. A finding blocks only for a concrete material defect against the operator-approved product contract. Speculative hardening, alternative architecture, and reviewer-invented invariants are non-blocking. If review invents requirements, stop that review loop and consult. Do not request or implement another repair merely to satisfy adversarial review.

Maintain a bounded goal. Use one exact heartbeat only while waiting for Episode or Expert work. The operator alone decides scope, product direction, merge, abandonment, and cleanup.
