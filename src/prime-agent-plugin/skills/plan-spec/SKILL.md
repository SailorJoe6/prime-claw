# Plan a retained specification

Use `plan_spec(location)` for an operator-selected retained
`.ralph/plans/future/<slug>` folder. No custom slash command is required. The
tool loads the project's canonical customizable
`.prime-claw/workflows/plan-prep.md` and `plan-spec.md` policy, including its
currently supported retained `.ralph/skills` fallback. Keep detailed procedures
there. Read `/skill:goals-and-heartbeats` unless it is already in context.

Bind the exact project-relative folder. If it is missing or materially
ambiguous, ask; do not search for, select, invent, or substitute a folder.
This route preserves frozen grandfathered specifications and living plans;
it does not author new folders, migrate ownership, or retire retained work.

Preserve the actual operator instruction, exact location, and approved scope
through preparation and compaction. Explicit conditional authority such as
“plan this specification, then implement it when ready” may authorize that
sequence without fresh approval solely because planning ended. Planning alone
does not authorize implementation. The canonical readiness review still applies.
Clarify material ambiguity, missing authority, or scope expansion.

Call `plan_spec` once with the exact `location`. Successful admission queues
preparation and one canonical planning follow-up; it does not prove compaction,
plan completion, or implementation readiness. End the turn after admission.
Report failure or uncertainty without automatic retry or another admission.
Planning creates no Episode and grants no merge, abandonment, activation,
restart, cleanup, or retained-plan deletion authority.
