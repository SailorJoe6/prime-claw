# Hand off the current pass

Use `ralph_handoff(guidance?)` when the operator clearly asks to hand off the
current Ralph implementation pass. No custom slash command is required. The
tool loads canonical `.prime-claw/workflows/handoff.md` and the sole `execute`
follow-up, preserving currently supported `.ralph/skills` fallback. Read
`/skill:goals-and-heartbeats` unless it is already in context. Keep the detailed
authority, durable-context, and compaction procedures in that project policy.

Bind the current pass, not replacement work. If the intended pass or handoff
objective is materially unclear, ask before calling. Pass only optional
operator-supplied bounded compaction focus; do not infer guidance, supply task
revisions, or expand scope. The canonical workflow resolves exact persisted
owner/task or retained-folder authority. Never switch modes or invent identity.

This is ordinary handoff, not Conversation supervision: an owning Conversation
continuing its exact managed Episode uses `prime-claw-oversee-episode` and its
bound `handoff_task_episode` or `handoff_spec_episode` operation instead. Do not
use ordinary handoff for blocked recovery, pause, consultation, merge,
abandonment, cleanup, or scope expansion.

Call `ralph_handoff` once. Successful admission queues handoff and exactly one
canonical execute follow-up. It does not prove compaction or execution completed.
End the turn after admission. Report failure or uncertainty without automatic
retry, direct execute invocation, a second assignment, or a new Episode. This
entry grants no product, merge, abandonment, restart, or cleanup authority.
