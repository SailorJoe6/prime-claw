### R-U3-2 — the two spawn/reap proofs

**(i) CLI one-shot, CWD-scoped.** `prime-agent -p --model anthropic.kimi-k3
--cwd /sandbox/episode-target "<read .cwd_sentinel via tool>"` — the agent's
file/shell tool reads a sentinel file by *relative* name; the token
(`CWDTOKEN857`) appears in the output only because the session's working
directory is the project. The sentinel is absent from the parent dir, so a
correct read proves CWD-scoping. (An earlier `pwd > file` variant was flaky
because the model chooses whether to run a tool; the read-a-sentinel form is
deterministic.)

**(ii) Daemon spawn → cwd → clean reap.** Driving the daemon's own client
protocol (`DaemonClient` over `/tmp/prime-agent-<uid>/daemon.sock`):
`create` with `config: { cwd: <project>, model, noSession: true }` returns a
session (`activeSessionId`) whose `get_state` reports `cwd =
/sandbox/episode-target`; `kill` reaps it and a follow-up `list` shows it gone.
Observed: `id=51b2fe893136 cwd=/sandbox/episode-target kill_ok=true
reaped=true` (and a second run `9b5b227a2589`).

This is the episode-spawn channel: a parent (or the orchestrator) spawns a
child session scoped to a project folder, lets it work, and reaps it — all
through the daemon, with the project as the child's CWD.

## R-U3-3 — the RLM automatic-preparation admission race (as observed)

Agent-driven spawn uses the **same daemon create/kill channel** proven above:
the host `rlm()` publishes a child session via the daemon and reaps it via
kill. The known hazard is the **RLM automatic-preparation admission race** —
the initial RLM task can be lost when a `session_start` extension starts a
child turn first. It is documented in `AGENTS.md` (Safe Spawn Protocol) and
`openclaw-setup/docs/prime-agent-rlm-preparation-race.md`:

- Do **not** put substantive work in the initial `rlm()` prompt.
- Spawn with a harmless bootstrap, then send the real task exactly once via
  `agent_message.send`.
- A returned RLM handle proves child publication, not task admission; do not
  resend a delivered task merely because a disposable bootstrap later reports
  `rlm_child_failure`.

Per **D6**, the two-message workaround is exercised only if the race manifests.
In this Phase 1 spike the race did **not** block the spawn/reap proof (the
daemon channel itself is reliable); a live in-sandbox parent→child `rlm()`
episode is deferred to Phase 4 (the episode loop), where the orchestrator runs
in-sandbox. **Non-blocking.**

## Gotchas recorded (for re-runs / Phase 2+)

- **`prime-agent daemon create` / `daemon kill` are not public CLI commands**
  ("Unknown command: daemon create"). The public surface is `prime-agent
  <create|list|stop|send|attach>`. The clean detached spawn/reap uses the
  daemon's client RPC (`DaemonClient.request({type:"create"|"kill"|...})`),
  reachable in-sandbox via a small node script against the daemon socket.
- **`prime-agent create <name>` is interactive**: positional args become the
  first *message* (it runs a turn), not a detached named spawn. For a reaped
  episode handle, use the daemon RPC (or `rlm()` from a parent), not
  `prime-agent create`.
- **Session names are unique per parent.** A name from a failed run (killed
  after create but before reap) stays registered; re-runs must use a unique
  name (the validator suffixes a timestamp) and always reap in a `finally`.
- **Cold daemon**: right after `status`/start, `create` can transiently return
  `success:false`; the validator retries with a socket-wait loop.
- **Model auth:** the spawn needs the Slice-3 credential bridge
  (`ANTHROPIC_API_KEY=$api_key` + `models.json` baseUrl → AI Gateway). The
  sandbox recreate wiped `~/.prime/agent/models.json`; it is re-staged from the
  operator's host config (non-secret, D11) — see `scripts/apply-phase1-providers.sh`
  / Slice 3. Default model must be `anthropic.kimi-k3` (the host default
  `claude-opus-4-7` is disabled on the gateway → 404).
- **Credential isolation (R-X-5):** only the `openshell:resolve:env:` placeholder
  is held in `ANTHROPIC_API_KEY`; the real gateway key is substituted at L7.
  `models.json` carries only the non-secret baseUrl. No credential material on
  sandbox disk.
