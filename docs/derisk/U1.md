## Findings log (accumulates; newest last)

### 2026-09-10 — Slice 1 operational facts

Facts future slices build on; each verified live against sandbox `prime-claw`
(OpenShell 0.0.116, image `ghcr.io/nvidia/openshell-community/sandboxes/base:latest`):

- **Denial signature.** Policy-refused egress surfaces to the client as curl
  exit **56** with `CONNECT tunnel failed, response 403`. The validator
  asserts on this; if a future OpenShell version changes the mechanism, the
  validator SHOULD fail — re-inspect, don't relax.
- **Policy is hot-reloadable.** `openshell policy set <name> --policy <file>
  --wait` applies `network_policies` changes to a running sandbox without
  recreate (observed v1→v2 live). Filesystem/process sections are static —
  changing them needs a new sandbox.
- **In-sandbox identity and layout.** User `sandbox` (uid/gid 998),
  `HOME=/sandbox`, workdir `/sandbox`. `curl` at `/usr/bin/curl`; `python3`
  at `/sandbox/.venv/bin/python3` (3.14.3).
- **`sandbox exec` is scriptable.** `openshell sandbox exec -n prime-claw
  --timeout N --no-tty -- bash -lc '<cmd>'` is the non-interactive workhorse.
- **Image pull is ~600 MB and noisy.** First `sandbox create` takes ~30 s on
  a warm connection; budget for it in fresh-environment reruns.
- **Install prerequisite for later slices.** The deny-by-default policy means
  *any* package/tool install from the network (npm, pip, apt) needs an
  explicit `network_policies` entry bound to the installing binary first.
  Slice 2 must add its install channel to `policies/phase1-sandbox.yaml`
  before installing prime-agent.

### 2026-09-11 — Slice 2 operational facts

- **prime-agent install channel.** The npm registry name `prime-agent` is NOT
  the install path (README: "Do not use the inherited npm package"). The
  documented installer resolves a versioned tarball from an R2 bucket
  (`pub-728493de92a943e2a9b2d17b4719f318.r2.dev`) via
  `app.primeintellect.ai/prime-agent/install.sh`. The release package then
  pulls npm runtime deps (registry.npmjs.org) AND bundled component tarballs
  (`prime-agent-core/-ai`) from the same R2 bucket — so node needs both hosts.
- **L7 proxy quirk: `%2F` reset.** The OpenShell proxy socket-resets any URL
  whose path contains an encoded slash (`%2F`, any case) — npm's canonical
  form for scoped packages (`@scope%2Fname`). Decoding to a literal slash
  works. `scripts/lib/npm-onload.js` patches `fetch`/`https.request` and is
  injected via `NODE_OPTIONS` for install legs. Symptom: `UND_ERR_SOCKET` /
  ECONNRESET, easily mistaken for network flakiness.
- **npm global prefix is root-owned.** `/usr/lib/node_modules` is not writable
  by `sandbox(998)`; installs need `NPM_CONFIG_PREFIX=/sandbox/.npm-global`.
- **`prime-agent --version` writes to stderr**, not stdout.
- **Kernel bootstrap.** `ensureKernelPython()` (dist/core/kernel/bootstrap.js)
  installs uv to `/usr/local/bin/uv` (not `~/.local/bin`), then a managed
  Python 3.11 + `prime-agent-runtime` into `/sandbox/.prime/agent/kernel-venv/`.
- **Persistent REPL is model-free to prove.** `ReplKernelManager`
  (dist/core/kernel/repl-manager.js) starts a kernel and holds Python state
  across `execute()` calls without any model credential. Slice 2 uses this to
  prove R-U1-4; the full session-start UX proof lands with Slice 3 creds.
- **Daemon persists across exec calls.** `prime-agent --mode daemon --offline`
  detaches, writes `/tmp/prime-agent-998/daemon.sock`, and is still alive on a
  later `openshell sandbox exec` (R-U1-3).

### 2026-09-11 — Slice 3 in progress: credential injection (R-U1-6 partial)

- **Mechanism confirmed.** OpenShell injects provider creds as opaque
  placeholders (`openshell:resolve:env:v<rev>_<key>`) under GENERIC env names
  (`api_key`, `access_token`, `refresh_token`, `account_id`) — NOT the
  SDK-conventional `ANTHROPIC_API_KEY` / `CODEX_AUTH_*` prime-agent reads. Real
  values never touch sandbox disk; the L7 proxy substitutes on the wire.
  Evidence: `evidence/phase1-credentials-20260911T155045Z.json`.
- **Codex leg RESOLVED.** `access_token` placeholder → api.openai.com returned
  `token_expired` (a real OAuth credential reached OpenAI). This proves the
  placeholder→L7-substitution→real-credential path works end-to-end. Caveat:
  the access token is expired and no refresh is configured.
- **Anthropic leg ANOMALY (open blocker).** `api_key` placeholder is NOT
  rewritten — Anthropic returns `invalid x-api-key`, i.e. the placeholder
  reached the API verbatim. Reproduced across the `claude-code` profile AND a
  custom `anthropic-api` profile, in both `x-api-key` and
  `Authorization: Bearer` headers, on a fresh sandbox with providers attached
  at create-time. Codex (same revision, same sandbox) resolves. Root cause not
  yet found.
- **Bedrock leg withheld by design.** Gateway log: "withholding static provider
  credential handle from endpointless profile" — the `aws-bedrock` profile is
  declarative-only (bridge-fronted); it injects nothing. R-U1-6 for bedrock
  requires the bridge-fronted shape or the SigV4 follow-up (out of Phase 1
  scope; document as a constraint).
- **Consumption-path gap.** prime-agent reads `ANTHROPIC_API_KEY` /
  `CODEX_AUTH_*` from env; OpenShell injects generic names. A mapping bridge
  (e.g. `export ANTHROPIC_API_KEY="$api_key"`) is required. prime-agent's
  env-vs-auth.json precedence not yet confirmed.
- **Operational hazards.** (1) `docker restart` on the sandbox container wedges
  the gateway phase at `Error`; supervisor re-registration does NOT clear it —
  recovery is delete+recreate (safe: all state is reproducible from committed
  apply scripts). (2) The shared `active_gateway` pointer flipping between
  `nemoclaw`(8080) and `openshell`(17670) caused container poisoning
  (`OPENSHELL_ENDPOINT` baked to the wrong gateway) and provider-record
  confusion. Now pinned to `openshell`; prime-claw runs only on 17670.

### 2026-09-11 — Slice 3 CORRECTION (D12): wrong endpoints; gateway-fronted host inference

The Slice 3 probes above targeted provider-native hosts (`api.anthropic.com`,
`api.openai.com`) via the `claude-code` / `codex` provider profiles. That was
the wrong target. Studying all three host configs together
(`auth.json` + `models.json` + `settings.json`, per D12) shows the host
prime-agent instance is **gateway-fronted**: `models.json` repoints every
provider to `https://ai-gateway.zende.sk` (`/anthropic`, `/v1`, `/bedrock`),
sharing ONE gateway API key; the default model `anthropic.kimi-k3` hits the
gateway's `/anthropic` path. The codex OAuth leg resolving against real
`api.openai.com` was the host-bound **exception**, not the rule. The
"anthropic resolution anomaly" was an artifact of testing endpoints the host
never uses.

**Revised Slice 3 target:** one OpenShell provider carrying the gateway key +
an endpoint profile for `ai-gateway.zende.sk`; carry the `models.json` baseUrl
overrides into the sandbox so prime-agent targets the gateway; prove the
default `anthropic.kimi-k3` call through the proxy. See DECISIONS.md D12 and
REQUIREMENTS.md R-U1-6 (corrected).
