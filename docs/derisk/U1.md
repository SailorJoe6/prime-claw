### 2026-09-10 — Slice 1 operational facts

Facts future slices build on; each verified live against sandbox `prime-claw`
(OpenShell 0.0.116, image `ghcr.io/nvidia/openshell-community/sandboxes/base:latest`):

- **Denial signature.** Policy-refused egress surfaces to the client as curl
  exit **56** with `CONNECT tunnel failed, response 403`. The validator
  asserts on this; if a future OpenShell version changes the mechanism, the
  validator SHOULD fail — re-inspect, don't relax.
- **Policy is hot-reloadable.** `openshell policy set <name> --policy <file>
  --wait` applies `network_policies` changes to a running sandbox without
  recreate (observed v1→v2 live). Filesystem/process sections are static —
  changing them needs a new sandbox.
- **In-sandbox identity and layout.** User `sandbox` (uid/gid 998),
  `HOME=/sandbox`, workdir `/sandbox`. `curl` at `/usr/bin/curl`; `python3`
  at `/sandbox/.venv/bin/python3` (3.14.3).
- **`sandbox exec` is scriptable.** `openshell sandbox exec -n prime-claw
  --timeout N --no-tty -- bash -lc '<cmd>'` is the non-interactive workhorse.
- **Image pull is ~600 MB and noisy.** First `sandbox create` takes ~30 s on
  a warm connection; budget for it in fresh-environment reruns.
- **Install prerequisite for later slices.** The deny-by-default policy means
  *any* package/tool install from the network (npm, pip, apt) needs an
  explicit `network_policies` entry bound to the installing binary first.
  Slice 2 must add its install channel to `policies/phase1-sandbox.yaml`
  before installing prime-agent.
