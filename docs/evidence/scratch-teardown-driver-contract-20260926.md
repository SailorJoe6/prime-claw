# Scratch daemon teardown driver review contract (not executable approval)

This is a bounded design contract for the prime-claw builder's **separate** isolated Prime Agent probe. It follows the [retained-root wrapper EXPERT PASS](scratch-probe-expert-pass-c6a5ac4-20260926.md) and the [teardown](scratch-teardown-source-audit-20260926.md) and [tool-root](toolroot-faux-provider-source-audit-20260926.md) read-only source audits. The wrapper is reviewed; **no native scratch daemon or socket has been started**. The active Phase 3a EPISODE and live identity remain untouched. Exact pinned source: Prime Agent v0.9.6 `e260085dd8f742e0def3d871860c9a888b114851`.

## First driver slice: teardown smoke only

- One explicit `--run-smoke` path may start only a **new** scratch default-socket daemon, with no session, provider prompt, custom socket, external credentials, or unrelated project state. Do not use `--no-session`: public `daemon start` rejects it (`cli/daemon-command.ts:586-589`). An ordinary invocation must be dry-run/preflight only. Tests use injected fake native CLI and fake OS observations; they must not start the installed binary.
- Invoke the driver **inside** `scripts/run-prime-agent-probe.sh --retain-root` in a single wrapper invocation. Require `PRIME_CLAW_PROBE_ROOT` to be a physical `/tmp/pcp.*` real directory owned by the current uid with mode 0700. Require exact co-rooted `HOME`, `TMPDIR`, `PRIME_AGENT_CODING_AGENT_DIR`, `PRIME_AGENT_SESSION_DIR`, owner-only real subdirectories, no symlinks, and default supervisor/longest worker encoded path <=103 bytes. Resolve and record the exact installed CLI binary before mutation; never use a different binary for start, ps, or shutdown. Fail on inherited worker routing/provider credentials. Do not open credential stores.
- Preflight must establish a **zero, uniquely owned** namespace before any start: no sockets/listeners/open root references, process identities, worker descriptors, supervisor registry records, or unexpected files; `prime-agent daemon ps --json` must be valid `[]` under the same env; independent `lsof` and `ps` scans must succeed. An ambiguous/failed scan or any existing occupant blocks start **and also forbids shutdown**, because the driver has not established ownership. Retain the root and evidence.
- Admit exactly one `prime-agent daemon start` attempt with the wrapper's isolated env, default socket, `--offline --no-extensions --no-skills --no-prompt-templates --no-context-files --no-tools`, bounded timeout, and cwd under that same root. `--offline` is not proof of no network; this first slice does not prompt. Record a bounded result and the exact command/CLI identity. After a successful start, capture supervisor hello/daemon-ps socket and PID, OS-owned socket references and PID + process-start identity. If a start times out, fails, or returns malformed data, mark the **experiment** uncertain; never retry it. An `already running` response or newly observed foreign identity revokes scratch ownership: do **not** shut down a possibly competing daemon, preserve the root, and consult.
- **Only after an owned start was attempted**, freeze new admissions and invoke exactly one bounded top-level `prime-agent shutdown --force --json` under the **same** HOME/TMPDIR/agent/session dir, even if start outcome is uncertain. Do not substitute per-socket `prime-agent daemon shutdown` or pass `--daemon-socket` to top-level shutdown. Require exit 0 and JSON object with `stopped` and `failed` arrays, `failed=[]`, and every reported socket path inside the private root. A timeout, nonzero exit, malformed output, or nonempty `failed` remains **unresolved even if independent scans later look empty**. No retry after an uncertain shutdown.
- Independently perform two bounded post-shutdown scans separated by a quiet interval: `daemon ps --json`, all OS Unix listeners and root file/cwd references (not filtered by process title alone), captured PID **and start identity** plus possible replacements, socket namespace, supervisor registry, and worker descriptors. All scans must succeed and agree. Allow retained stale files as evidence only if no live socket/process/root reference exists; malformed/unknown descriptor is unresolved. If a caller timeout could leave shutdown in progress, do not start a second mutation or delete the root. Only a successful native shutdown response **and** complete independent empty observations support a bounded `stopped` verdict. These are time-bounded observations, not a guarantee against an undiscoverable or delayed actor.
- Always retain the private root and write a redacted, bounded JSON record of baseline, launch, shutdown, postflight and classification. Do not print descriptor authentication tokens, credential material, arbitrary environment dumps, or raw private transcripts. No `rm -rf`, broad/global shutdown, `pkill`, process-group kill, or arbitrary PID signals in driver or tests. On any uncertainty: quarantine the root, report exact action needed, and do not rerun a mutating step.

## Required fake acceptance tests before a native attempt

1. Preflight empty; fake one start; valid top-level shutdown JSON (`failed=[]`); two empty OS/daemon-ps scans; captured PID+start identity gone => `stopped`, root retained. Assert exact same isolated env and binary at every command, one start and one shutdown.
2. Nonempty/ambiguous preflight, failed `lsof`/`ps`/`daemon ps`, existing registry/descriptor/socket, symlink or wrong-owner root => no start **and no shutdown**, retained evidence.
3. Start timeout/transport loss/malformed response => at most one owned scoped shutdown attempt, experiment unresolved, no retry; a failure before owned start admission invokes no shutdown.
4. Shutdown timeout/nonzero/malformed JSON/nonempty `failed`/out-of-root stopped path => unresolved even with empty OS scans, one shutdown attempt, retained root.
5. `daemon ps` empty while lsof finds a worker/kernel or socket, captured PID persists or has a changed start identity, descriptor invalid/missing start ID, new listener between quiet scans, unreadable lsof/ps, or socket permission error => unresolved; no cleanup or signals.
6. Any custom `--daemon-socket` is rejected by this first slice. Every output/error path proves redaction of `authenticationToken` and absence of inherited credentials.

## Separate next slice and review gate

A successful smoke only verifies bounded shutdown of one isolated default-socket scratch daemon; it does **not** establish safe EPISODE handoff, fork causation, or execution-time tool cwd. To test rebind/tool roots, separately review an extension of the driver with the exact pinned local faux provider and deterministic **scratch-only** prompt. Prove that it cannot fall back to a real provider or network, capture actual `ipython os.getcwd()`, kernel `bash()` pwd, and relative sentinels, and keep the same teardown invariant. If that boundary or exact process identity cannot be proved, stop and consult Joe; never weaken live cwd guards or switch to fork-to-fresh by inference. The first driver implementation and its non-daemon fake tests require a fresh exact-commit independent EXPERT review **before** `--run-smoke` or any native daemon launch. A reviewer PASS is evidence, not live/merge authority.

The [scratch teardown driver candidate](scratch-teardown-driver-candidate-20260926.md) and its fake-test evidence are an **unreviewed PRE-RUN BLOCK** until that fresh exact-commit review passes. The linked record does not authorize native use.
