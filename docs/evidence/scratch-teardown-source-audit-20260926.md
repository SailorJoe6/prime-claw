## Direct scout report

Read-only v0.9.6 design review (pinned source e260085; no commands, sockets, edits, or probe run):

**Scope:** Invoke the *top-level* `prime-agent shutdown --force --json` only inside the retained, private HOME/TMPDIR/agent-dir/session-dir root. This dispatches `runShutdownAll`, unlike `prime-agent daemon shutdown`, which connects to just one selected socket (`src/cli/public-command.ts:288-292`; `src/cli/daemon-command.ts:151-152,251-269`). The state matcher claims the private default socket dir and agent-dir sockets plus registered custom paths; another HOME is excluded only if TMPDIR/socket namespace is also isolated (`src/modes/daemon/daemon-state-root.ts:7-11,27-52,54-72`; `src/modes/daemon/daemon-socket.ts:279-282`). Prefer default socket. A custom socket outside these roots is out of shutdown scope if registry write is absent/lost; if unavoidable, require canonical path *inside* private agent-dir, validated encoded pathname budget, and explicitly match the registry/OS listener before admission. Do not treat `--daemon-socket` on top-level shutdown as a scoped selector.

**Driver proposal (separate review before any launch):** (1) Retain wrapper root; assert canonical private root, mode/owner, env and exact binary identity; no deletion at any exit. Snapshot the empty root before start, including `daemon ps --json` under the same env, supervisor owner registry, `agent/daemon-workers`, default and worker socket namespace, independent OS `ps` and `lsof` scans of root/socket references. Reject any initial process, socket, descriptor, unknown/failed scan or unrelated path. (2) Capture process identity as PID + UTC/locale-pinned start time, argv/comm, parent, cwd and owned socket; capture supervisor hello/list IDs and worker descriptor PID+start-ID/socket/supervisorSocketPath/lifecycle, but do NOT emit descriptor authenticationToken (`src/core/session-lease.ts:147-180`; `src/modes/daemon/daemon-supervisor-ownership.ts:31-43`; `src/modes/daemon/daemon-worker-protocol.ts:146-174`; `src/modes/daemon/daemon-supervisor.ts:3482-3515,3557-3580`). Reconcile every observation to private canonical paths and captured identities; descriptor alone or argv alone is never signal authority. (3) On *every* path, including start/create/restart timeout or malformed response, freeze new admissions, do not blind-retry mutation, run one bounded root-scoped shutdown command, capture raw exit/stdout/stderr, parse exactly JSON object `stopped: array`, `failed: array`; nonzero, parse failure, nonempty failed, command timeout = unresolved. Shutdown itself has a 10-s residual-listener convergence limit and one-second quiet period, and may return failed entries (`src/cli/daemon-ps.ts:83-89,533-574,577-595,672-695,754-806`). (4) Regardless of apparent success, independently rescan OS root/socket references (including non-listening processes/child kernels), captured PID+start identities, lsof sockets/root files, registry/descriptors, `daemon ps --json`, and socket directory twice with a bounded quiet interval. Require zero *live* scratch processes/listeners/open root refs, no new identity, and all scans successful; stale files/records can remain as retained evidence. Only then mark stopped; never remove retained root in this driver. Any uncertainty => blocked/quarantined root, exact output and identities retained, human review; no broad kill or global cleanup.

**Important limits:** `discoverDaemons()` uses an OS listener sweep, default socket files and *valid* tracked descriptors; scans can silently degrade if `ss`/`lsof`/`ps` fail, invalid descriptors are skipped, and `ps --json` alone cannot prove zero (`src/cli/daemon-ps.ts:194-217,238-258,361-412,1030-1089`). The built-in forced shutdown itself can SIGTERM/SIGKILL verified listeners, process groups, and children; its `shutdownDaemon` only proves no socket acceptance, not no process/root ref (`src/cli/daemon-ps.ts:840-879,960-1020,1092-1137,1285-1314`). A caller timeout can race a still-running shutdown; block further mutation and retain root until that invocation and all observed processes settle. OS snapshots are time-bounded observations, not absolute proof against a future delayed respawn, undiscoverable process, PID race, bad privileges, or external actor. This design cannot prove fork causation, runtime tool cwd, or that an incident-matching supervisor rebind is safe; those need separately reviewed isolated execution probes. No live episode change follows.

**Failure matrix / acceptance tests (all fake CLI + injected fake ps/lsof, no daemon):** clean zero baseline + valid shutdown JSON + two quiet empty full scans => stopped, retained root; failed[]/nonzero/malformed JSON/timeout => unresolved retained root; start/create uncertain or shutdown transport loss => still attempt bounded scoped shutdown once, then unresolved unless complete evidence; daemon ps empty while lsof shows worker/kernel or socket => unresolved; descriptor malformed/missing start-ID or mismatch, socket path outside root, PID reuse, two owners for one socket, unknown supervisor, custom socket missing registry => reject/retain; delayed replacement between scans, new root ref, failed lsof/ps permission or truncated output => unresolved; fake CLI records exact isolated env, top-level argv, one shutdown attempt, no signal/delete; tests assert redaction of authenticationToken. Source test precedents cover pure shutdown plans and state-root matching (`test/daemon-ps.test.ts:105-143`; `test/daemon-state-root.test.ts:66-106`). Acceptance is only a separately reviewable *driver*, not approval to run it.
