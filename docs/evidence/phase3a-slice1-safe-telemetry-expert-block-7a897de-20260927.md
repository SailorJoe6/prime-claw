## What the official release actually supports

All source links below are pinned to **v0.0.116**, not the current website’s v0.1.x. Local `openshell --version` also reports 0.0.116; I did not attest the running supervisor image/build digest.

1. **`--level debug` does not turn on supervisor debug logging.** Installed `openshell logs --help` calls it a minimum display level. [CLI source](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/crates/openshell-cli/src/run.rs#L6957-L6996) passes it as `log_min_level`/`min_level`. [LogPushLayer](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/crates/openshell-supervisor-process/src/log_push.rs#L28-L88) reads `OPENSHELL_LOG_PUSH_LEVEL` when constructed, defaults to INFO, and pushes OCSF **shorthand**, not the full event. [Supervisor startup](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/crates/openshell-sandbox/src/main.rs#L570-L652) constructs the filters; the ordinary file filter is INFO. The [runtime settings registry](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/crates/openshell-core/src/settings.rs#L110-L146) has `ocsf_json_enabled`, but no `log_level` setting. I found no supported hot-reload control for these debug filters.

2. **An error may already be generated at INFO but hidden in shorthand.** The [TLS handler](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/crates/openshell-supervisor-network/src/proxy.rs#L2212-L2247) emits a failure event with `message = "TLS relay error: {e}"` and a destination. The [shorthand formatter](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/crates/openshell-ocsf/src/format/shorthand.rs#L193-L257) normally omits that message when structured destination/detail exists and there is no DENIED action. [OCSF emission](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/crates/openshell-ocsf/src/tracing_layers/event_bridge.rs#L31-L50) uses tracing INFO. Therefore “no reason visible in INFO shorthand” does **not** establish “no useful error was emitted.”

3. **JSONL is documented and live-toggleable, but not read-only to enable.** [Release documentation](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/docs/observability/ocsf-json-export.mdx#L10-L38) documents per-sandbox `ocsf_json_enabled`, the next poll cycle (default 10 seconds), no restart, and `/var/log/openshell-ocsf.YYYY-MM-DD.log`. [Lines 189–193](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/docs/observability/ocsf-json-export.mdx#L189-L193) distinguish full JSON from shorthand. Reading an already-enabled retained file is a supported read-only option. Turning export on does not reconstruct older records. It exports sandbox events generally, not just one request, so unfiltered export is not privacy-safe.

4. **Even full JSON does not satisfy the requested discriminator.** The TLS handler groups client TLS termination, upstream TLS establishment, and HTTP relay under the same error wrapper. Its failure event supplies neither a connection ID, client PID/source socket, nor a typed failing leg or RST direction. [TLS helpers](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/crates/openshell-supervisor-network/src/l7/tls.rs#L170-L197) propagate errors without adding those stage labels. Some reset/EOF errors are [classified as benign and only debug-logged](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/crates/openshell-supervisor-network/src/proxy.rs#L6324-L6338). Crucially, this release’s [`metadata.uid` is the sandbox ID](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/crates/openshell-ocsf/src/builders/mod.rs#L200-L221), **not** a request/flow ID. Do not borrow newer documentation’s UID semantics.

5. **ALLOWED is not upstream TLS success.** In this release, [upstream dial precedes CONNECT 200 and ALLOWED](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/crates/openshell-supervisor-network/src/proxy.rs#L2095-L2144), while upstream TLS follows client-facing TLS. That ordering can constrain a release-matched trace; it does not prove the live deployment’s exact error. A client handshake with the OpenShell Sandbox CA is not proof of origin TLS success. Gateway [OTLP documentation](https://github.com/NVIDIA/OpenShell/blob/v0.0.116/docs/reference/gateway-config.mdx#L216-L238) covers gateway RPC/HTTP/store/driver spans, not a supervisor upstream socket/reset trace.
