## Direct scout report

No public direct daemon `execute_ipython` command was found; if “without prompts” forbids even a local scripted prompt, daemon ipython measurement is NOT presently possible via a supported command. No daemon/CLI/socket/test was run, and this route remains unvalidated in the installed binary.

Concrete source-backed route: The existing exact-source `packages/coding-agent/test/fixtures/compiled-artifact-extension.ts:3–40` registers `@earendil-works/pi-ai` `registerFauxProvider` via `pi.registerProvider(... streamSimple: provider.streamSimple, apiKey: "offline-test")` and scripts actual `ipython` calls using `fauxAssistantMessage(fauxToolCall("ipython", {code: ...}), {stopReason:"toolUse"})`; the scripted callback inspects tool results. Its compiled binary integration uses `--offline --no-context-files --no-extensions -e <fixture> --provider artifact-faux --model artifact --tools ipython -p ...`, with isolated HOME/agent-dir and disabled retry (`test/compiled-artifact.test.ts:157–178,379–396`; `:80–94`). Custom `streamSimple` is an advertised extension API (`src/core/extensions/types.ts:1127–1137,1198–1210`; `docs/custom-provider.md:343–365,509–520`); this is genuinely local in the fixture, unlike `--offline` alone, which source test shows can still contact Bedrock (`test/compiled-artifact.test.ts:338–375`). Adapt this test fixture **only inside retained private scratch**, with deterministic code to print `os.getcwd()`, `Path('SENTINEL').resolve()` plus its contents, and `(await bash('pwd; cat SENTINEL')).output` (a distinct sentinel in builder/worktree); check `toolResult.isError`, exact expected result count, timestamps, and pid so an “ok” assistant is not mistaken for evidence. Neither inject actual provider credentials nor admit any inherited provider environment. This invokes the sandbox local scripted `prompt` but issues no external provider request; a direct `execute_bash_and_wait` protocol command (`src/modes/daemon/daemon-protocol.ts:651`; `daemon-mode.ts:4890–4898`) independently measures *session built-in bash* cwd, NOT kernel `bash()`.

For a scratch-only rebind trial (not recommendation for live episode): first create private short-root builder/worktree/sentinel/session stores and local extension; validate socket byte budgets and exact ownership before starting. Start only scratch daemon with **default** local provider/extension config and isolated env, `daemon create --cwd <worktree> --provider <faux> --model <faux> --extension <scratch-extension> --session-dir <scratch-session-dir>` or programmatic `DaemonClient.request({type:'create', lifecycle:'resident', config:{cwd,sessionDir,provider,model,extensions...}})` after verifying actual config key; request shape is `src/modes/daemon/daemon-protocol.ts:413–424`, CLI parsing `src/cli/daemon-command.ts:347–414,465–475,508–512`. Default provider config must survive supervisor restart: descriptor roster rewrite drops per-create config (`daemon-supervisor.ts:4560–4569,4912–4928`), while worker recovery merges daemon defaults with retained create config (`:3477–3515`), and worker only overrides header cwd if the *command* config carries cwd (`daemon-mode.ts:1872–1885,1997–2007`; `session-manager.ts:2695–2706`). Confirm local model is selected after recovery before prompting; otherwise stop instead of falling back to a real provider. For incident-adjacent supervisor replacement use public scratch `daemon restart` (`cli/daemon-command.ts:245–249`; `daemon-supervisor.ts:2574–2583,7520–7605`) rather than worker SIGKILL. It is not a perfect recreation of the observed SIGTERM adoption. A same-file `switch_session` with scratch `cwdOverride` can force a *synthetic* builder/worktree mismatch, but does NOT explain live restart causation and is not transactional (`daemon-protocol.ts:654`; `agent-session-runtime.ts:409–450,251–276`); reserve as a separate scoped control, never live.

Capture BEFORE and AFTER for each exact `activeSessionId`, durable ID/file, header cwd (`get_session_header`), `get_state`, `list(all:true)`, supervisor/worker generations and pid, tool results and timestamps, scratch transcript JSONL, kernel artifact dir snapshot/manifest/stderr, descriptor/logs, sentinel paths. `get_state` and active list derive manager cwd (`daemon-mode.ts:4991–4993`; `daemon-session-list.ts:291–299,362–393`) but list uses asynchronous roster (`daemon-extension-binding.ts:71–84`; `daemon-mode.ts:7303–7319,7370–7416,8052`). Bound repeated **read-only** state/list checks by deadline until same ID/file/cwd/route, or record nonconvergence; a one-shot mismatch proves nothing. The new tool provisioner receives runtime `_cwd` (`agent-session.ts:10800–10829`), starts Python with its cwd (`core/tools/ipython.ts:519–535`; `core/kernel/repl-manager.ts:374–382`), and kernel `bash()` uses *current Python os.getcwd()* (`prime-agent-runtime/src/rlm/bash.py:312–325`). The kernel revives snapshot before bootstrap (`core/tools/ipython.ts:558–597`), so compare pre/post kernel pid, snapshot presence, restore notice, os.getcwd(), bash pwd, and sentinel resolution rather than inferring current tool root from idle process cwd or manager metadata. Avoid first-cell `os.chdir`; record if any injected extension/user snapshot code changes cwd.

Shutdown is NOT proved safe simply from a successful `shutdown --force --json`: CLI forwards to target socket (`cli/daemon-command.ts:108–131,150–152,260–270`), supervisor ACK precedes asynchronous shutdown (`daemon-supervisor.ts:2577–2583`); shutdown loops known workers, can leave tombstones, and checks persisted descriptors (`:7520–7561`), but descriptor loading skips invalid/foreign entries (`:1651–1683`) and individual stop can time out even after SIGKILL (`:6996–7056`). The bundled compiled test has its OWN stronger test cleanup (request shutdown, capture hello supervisor PID, terminate that PID on failure, track child handles) but does not by itself certify unattended production teardown (`test/compiled-artifact.test.ts:180–203`). Require exact scratch socket/descriptor/PID/start-id/argv verification, bounded post-shutdown process and listener check (including replacements), retain root/artifacts on ANY uncertainty; no global shutdown, broad kill, or root deletion until zero exact-owned processes. An uncertain mutating request must not be blindly replayed. Need separate preflight/teardown review before launch.

## Owner boundary

An isolated deterministic local `prompt` is materially different from sending a real provider prompt, but remains a mutating scratch action and needs an exact reviewed driver, no credential inheritance, a network-denial or equivalent local-only proof, and safe shutdown evidence first. If the review cannot prove it cannot fall through to a real provider, do not prompt or substitute a provider; consult the operator if the no-prompt boundary is absolute. A non-daemon fallback would be narrower evidence only. Neither report changes the live episode, the fork design, or host guards.
